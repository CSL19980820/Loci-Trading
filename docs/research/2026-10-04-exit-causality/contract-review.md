# 退出遮罩的时点语义审查

2026-10-04。范围仅为 `strict_price_masks → _resolve_exit → _tradable_exit` 及必要文档/测试。未改生产源码、冻结算法、计划或历史结果，未读取真实订单来选择有利案例，未计算任何真实替代收益。

**已确认的问题是收盘退出代理与盘中触价退出共用了同一个遮罩。** strict 模式明确约定收盘跌停延期，代码也确实这样实现；但该遮罩随后覆盖了原生 `one_word_down`，同时阻止当日已经触发的盘中止损/止盈。单事件合成验证证明：只改变触发日最后的收盘价，保持开盘、高低和此前触价路径相同，可以改变更早止损是否执行。这是模拟器的执行时点语义问题，不能称为选股策略增强；也不能由此直接断言取消遮罩后的模拟价格是真实可成交价格。

`execution_contract.py` 的现有遮罩在已提交版本 `26c8744` 中已存在；当前 `engine.py` 的工作区差异仅为摘要中收益指标名称，未更改这条执行路径。本次研究复用了这一既有行为。提交和文档没有足够证据重建开发者最初意图，不能把“本应仅用于收盘单”当作已知历史事实。

## 源码调用与混用位置

1. 原生非 strict 路径在 [`engine.py`](../../../src/backtest/application/engine.py)，107—125 行用 `np.isclose(high, low)` 判整日同价，再以收盘相对前收区分涨跌方向。口头说的 `H == L` 在实际代码中有数值接近容差；它本身也是日 K 代理，不是盘口证明。
2. [`strict_price_masks`](../../../src/backtest/application/execution_contract.py)，26—42 行没有接收 H/L。它使用最近有效原始前收及因子构建实际价格坐标的涨跌停参考，返回 `open >= upper - .005`、`(close <= lower + .005) | ~known` 和 `known`。第二项表示收盘跌停或参考未知，不能解释为整日一字板。
3. `run_backtest` 在 [`engine.py`](../../../src/backtest/application/engine.py)，189—196 行把第二项覆盖到名为 `one_word_down` 的变量；280—294 行将它传给 `_resolve_exit`。
4. `_resolve_exit` 在 398—413 行从 T+1 起检查 `low <= stop` 或 `high >= target`，然后把同一个遮罩传给 `_tradable_exit`。419—421 行的到期收盘退出也复用它。没有订单时点分支。
5. `_tradable_exit` 在 462—471 行先排除停牌和遮罩为真的整日。只有触发日获准退出时才用触发价/跳空价；一旦延期，就使用后续获准日期的收盘价。因此 `exit_reason="stop_loss"` 表示最初触发原因，最终毛亏不必达到止损线，甚至可在延期后反弹。不能用“stop_loss 的最终毛亏至少 6%”作为全体交易断言。

倍量阴研究也走相同路径：[`research_double_yin_redesign.py`](../../../tools/research_double_yin_redesign.py)，194—202 行构造 `data["strict_down"]`；[`research_double_yin_vwap.py`](../../../tools/research_double_yin_vwap.py)，116—147 行复用该执行面板；[`research_double_yin_delayed_execution.py`](../../../tools/research_double_yin_delayed_execution.py)，313—318 行将 `strict_down` 直接作为 `one_word_down` 传入退出器。价格基准虽改为 P5×因子，这个退出遮罩没有改变。

## 一个合成事件的可复现证据

只构造一笔交易，未加载数据库、行情、策略候选或真实成交文件。T 日入场 basis=10，止损线 9.4，T+3 计划到期，因子均为 1、量均为正。T+1 的有效跌停参考为 9.0。

| 日 | O | H | L | C |
|---|---:|---:|---:|---:|
| T−1 | 10.0 | 10.2 | 9.8 | 10.0 |
| T | 10.0 | 10.2 | 9.8 | 10.0 |
| T+1 | 9.8 | 10.0 | 9.0 | **仅这里在 9.0 和 9.2 间变化** |
| T+2 | 9.7 | 9.8 | 9.3 | 9.6 |
| T+3 | 9.6 | 9.7 | 9.5 | 9.6 |

两种收盘都容许相同的合成早期路径 `9.8 → 10.0 → 9.4 → 9.0`，随后分别收于 9.0 或反弹收于 9.2。T+1 都有 H>L，都触及相同止损线，差别只在后来的收盘。

| T+1 最终 C | 传给未修改退出器的遮罩 | T+1 被整日阻止 | 引擎返回 |
|---|---|---|---|
| 9.0 | 现有 strict 收盘遮罩 | 是 | T+2 收盘 9.6，原因仍为 `stop_loss` |
| 9.2 | 现有 strict 收盘遮罩 | 否 | T+1 止损代理 9.4 |
| 9.0 或 9.2 | 原生一字板遮罩，作为语义对照 | 否 | 均为 T+1 止损代理 9.4 |

这证明当前 strict 行为依赖于盘中触发之后的收盘，不证明任何真实订单一定能在 9.4 成交。原生遮罩只用于合成对照，没有应用到任何真实历史，也不是已采纳的替代合同。

可复现文件：[synthetic-contract-probe.py](synthetic-contract-probe.py)、[synthetic-event.json](synthetic-event.json)。脚本只调用未修改的遮罩与退出器，保存入场/触发/退出价格和源文件哈希，未计算收益。通过隔离入口运行，临时可变目录已由入口清理。

根代理另用同一 fixture 独立验证了上述盘中场景，以及 O 改为 9.3、开盘已穿 9.4 止损但仍高于 9.0 跌停线的缺口场景。缺口场景仅将晚收盘从 9.0 改为 9.2，现有 strict 返回从 T+2 的 9.6 改为 T+1 开盘 9.3。4 个独立分支和 3 个源码哈希检查均通过，见 [root-synthetic-check.json](root-synthetic-check.json)。这些是模型因果依赖证据，不是订单真实成交证据。

## 如何定性

- **已证实的接口与时点缺陷：** 命名及调用把“收盘无法按约定卖出”当成“当日早先无法触价退出”，同日后续收盘可以改变此前止损的模拟结果。若业务语义是盘中触发即按 OHLC 撮合约定退出，该行为不符合该语义；问题发生在执行模拟，不是选股信号偷看未来。
- **有文档依据的近似：** strict 对收盘跌停采用不成交并延期的保守约定，以及延期后按首次允许日收盘撮合，都已存在。不能在修正盘中时点时顺手撤掉收盘单的该约定，或者把后续收盘退出悄悄换为下一开盘。
- **尚不能仅凭日 K 证明的事实：** H>L 不保证本订单在触发后有足够买盘，也不能给出开板、重新封板、触发及排队的完整顺序；低价触及仅支持 OHLC 代理，不能证明价差、滑点、数量和实际成交。将遮罩全局替换为 `H == L` 并把所有其余订单按止损价成交，不等于完成真实执行校正。

## 最小合理的隔离修正方案

当前仅提出方案，未实施替代退出或回算。最小下一步已经收敛为**首个止损触发日开盘缺口的有限敏感性**，不扩大到所有盘中触价。

1. 在独立研究执行适配器中分开**盘中触价日判断**与**收盘退出判断**，保留同一涨跌停参考、原始价格/经济因子坐标、T+1、原入场 basis 和持有期。不要向一个含糊的 `one_word_down` 参数继续塞两种语义；也不要先全局改生产 helper。
2. 原定收盘退出，以及确实无法在触发日处理而进入延期状态后的收盘退出，保留当前 `close <= lower + .005` 保守屏障及停牌/未知保护。后续退出仍按首次允许日收盘；任何改成开盘、开板价或继续等待触发价的做法属于另外的执行合同。
3. 只考虑原持有扫描期 T+1 至 T+3 内的**首个止损触发日**：该日 bar、量、因子、涨跌停参考均有效，经济开盘价已不高于原止损线，raw O 严格高于已知 lower+0.005，却因最终 C 跌停而被否决。在取数及真实替代收益前冻结该唯一条件，才可用该日 raw O 作为独立的开盘执行代理；保持原入场、名单、数量和费用。它避免需要推断盘中何时触价，但仍不证明本订单能以开盘价成交。
4. 开盘未穿止损而仅盘中 L 触发、开盘/代理卖价处于跌停线、开板再封板顺序、关键字段或参考未知等都不在这个替代集合。对成交证据不足的路径只附“尚未解决执行证据”标记，保留冻结合同中的闭合标签/收益，不改成取消或零；真实输入未知继续遵循原 unknown 合同。不能把“已有模型算闭合”与“实际可成交已证实”混为一谈。
5. 不修改到期收盘屏障、真实全天跌停/停牌延期及延期后的收盘合同；不在后续重试日另选开盘。若固定订单内符合该窄条件的发生率为 0，就报告 0 并停止，不能扩大成盘中触价、寻找有收益改善的子集或试新参数。若后续授权重算，应明确它是有限执行敏感性，不是完整因果修复，不回写旧证据或据结果重新提名。

仅改名称/文档可以消除错误解释，但不能消除晚收盘改变早止损的行为；直接改全局遮罩则会影响现有收盘单和多个调用方。上述开盘缺口切口是最小可检查范围，**本文 O=9.8 的盘中合成问题仍未由它修复**。将来要完整修正盘中路径，仍需独立冻结更细的成交证据与订单时点合同，不能用“更合理”替代证据。

| 场景 | 应核对的合同 |
|---|---|

| 非跌停价的跳空穿止损 | 保留 `min(open, stop)`，不能回填较好止损价。 |
| 开盘/触发价在跌停线、关键字段或参考未知 | 分别保留需顺序证据/unknown，不猜成交或用零贡献替代。 |
| T+1 与因子坐标 | 不新增当日卖出；触发价、涨跌停参考和最终记录的 raw 价格保持同一合同。 |

源文件和冻结研究文件均保持原样；本报告交付的是已复现的语义调查、明确限制及隔离方案，不是修复完成或新收益结论。
