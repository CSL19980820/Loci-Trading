## 1. 提醒模板

沿用仓内 `actionable_line.py` 的 `💰名称 · N层 · 买价 · 风险` 骨架，加强度分，止损位换成均线位：

```
💰星网锐捷(002396) 强82 · 买41.30 · 止41.04
   低40.00收复MA10 · 距高2日 · 回撤15.4% · 20日+80% · 筹码17.0%  涨幅甜区 回撤甜区 筹码偏密
```

**两行封顶**：第一行动作，第二行五项可自证的依据 + 命中的甜区标签。**不写层数**——分层收益尚未验证，写了就是给未验证的东西挂权威。完整字段在 JSONL 里。

`低53.48收复MA10` 就是触发的**全部定义**（当日最低 ≤ MA10 < 现价）——看到这两个数就能自己复核，不必相信脚本。

**只数不设上限。** 系统只负责把符合条件的都摆出来并按强度排序，不代替用户砍到三只。要限量时显式传 `--max-alerts`。层数（3/2/1）按强度给，是建议不是限制。

首轮实跑（2026-08-12，收盘快照）：市场宽度 74.47% 过闸、快照 5539 只、监控池 38 只、可判定 37 只、触发 1 只。

## 1.1 强度分：四项权重全部来自回测分档

**不是拍脑袋配的**，每一档的区间与方向都能追回 [`dragon-pool-trigger-chip-backtest`](2026-08-dragon-pool-trigger-chip-backtest.md) 的分档表：

| 项 | 得分 | 依据 |
|---|---|---|
| 20 日涨幅 50~100% | **+30** | 该档 394 笔、两段皆正、后段更优 |
| 20 日涨幅 0~20% 或 100~150% | +15 | 次优两档 |
| 20 日涨幅 20~50% | **0**（标「涨幅险区」） | **全表最差**（−2.049%/笔） |
| 距高点 ≤1 日 | **+25** | 最强单维（n=97、每笔 +1.852%、中位为正） |
| 距高点 2~3 日 | +15 | 次优 |
| 距高点回撤 10~20% | **+25** | ∩ 距高点 0-1 是全网格最强二维格（n=71、每笔 +2.928%、PF 1.993） |
| 回撤 5~10% 或 20~30% | +12 | 次优两档 |
| 筹码宽度 <15% | **+20** | 密集档 n=168、两段皆正、后段远优于前段 |
| 筹码宽度 15~25% | +12 | 偏密 |

满分 100。**20 日涨幅这一项不是「涨得越多分越高」**——实测与收益是 W 形非单调，50~100% 最好、20~50% 最差、≥100% 转负，所以险区不给分并显式标注。

上例 80 分 = 涨幅甜区 30 + 紧邻新高 25 + 回撤甜区 25 + 筹码 32%（超 25%，**这项 0 分**）。缺项就是缺，分数不虚高。

## 2. 信号定义

### 两段式

```
盘后/首轮：全市场截面算 20 日涨幅前 10 → 入监控池，滚动保留 20 个交易日
盘中每轮：只对池内票取现价与当日最高最低 → 判触发
```

「20 日涨幅进过全市场前十」需要全市场截面，按票取数不划算；盘中只需盯池内几十只（实测 38 只）。

### 触发（三条同时成立）

| 条件 | 判定 | 依据 |
|---|---|---|
| 探底回升收复 MA10 | `当日最低 ≤ MA10 < 现价` | 五条均线里 MA10 的两段皆正格最多 |
| 距 20 日最高 ≤ 3 日 | `HHVBARS(high,20) ≤ 3` | 要新高附近洗盘，不是深回踩 |
| 市场宽度 ≥ 55% | 全市场上涨家数占比 | 单此一条把全期收益从 −3.72% 拉到 +80.02% |

**不排除 ST**：实测按当前名称排除 ST 是自伤，那 203 只每笔 +4.39%、中位 +8.38%。

### 为什么不需要分钟线

`fetch_live_quotes_routed` 返回的 `low` 是**当日累积最低**，`price` 是现价，所以「盘中打到过 MA10、现在又收复」一次快照即可判定。10 分钟一轮的粒度失效方向是安全的：若先收复又跌破，扫到的是跌破态、不触发，而那种票本来也不该买。

盘中 MA10 用**动态口径**（前 9 日收盘 + 现价），与通达信盘中显示一致；日志同时记 `ma_prev`（昨日收盘算出的静态值）便于两种口径复核。

## 3. 观察期怎么跑

```powershell
# 单轮
.\.venv\Scripts\python.exe -m scripts.dragon_second_wave_live_scan

# 盘中循环（每 10 分钟一轮，与 skill_watch 的既有节奏一致）
while ($true) {
  .\.venv\Scripts\python.exe -m scripts.dragon_second_wave_live_scan
  Start-Sleep -Seconds 600
}
```

可调项：`--pool-top-n`（默认 10，**别调小**，收紧到 5 会让分档验证失去统计力）、`--breadth-min`（默认 55）、`--max-alerts`（默认 **0 = 不限**）。

### 回溯复盘

`--as-of` 指定过去的交易日会自动切到**回溯模式**：用那天的日 K 当快照（`price` 取收盘、`high`/`low` 取当日最高最低），行情源标成 `replay:日期`。

```powershell
.\.venv\Scripts\python.exe -m scripts.dragon_second_wave_live_scan --as-of 2026-07-15
```

回溯下触发式 `low ≤ MA < price` 正好退化成回测里用的日线等价式，可与研究结论直接对照。**首版没有这条路是个 bug**：`--as-of` 只改了日线基准、行情仍取实时，等于拿今天的行情配那天的均线，市场宽度也永远是今天的值。

### 分支覆盖

| 分支 | 触发方式 | 结果 |
|---|---|---|
| 弱市空仓 | `--breadth-min 99` | 宽度 74.47% 未过闸，触发票只记录不提醒 |
| 极小池 | `--pool-top-n 1` | 池 38→9 只；同一只票入池日从 8/03 变 7/30、当时涨幅 105.18%（≥100% 档只给 +15），强度 80→**65** |
| 历史回溯 | `--as-of 2026-07-15` | 宽度 **60.45%**（当日值），触发 3 只 |
| 历史回溯·弱市 | `--as-of 2026-08-06` | 宽度 **50.38%** < 55% → 择时闸门在历史日期上真的拦住了 |
| 筹码缺失 | 热景生物(688068) | 筹码显示 `-`，不崩、不用 0 冒充 |

**非单调评分被实证**：同一只票在 top-1 池里入池时已涨 105%，强度反而比入池时涨 59% 低 15 分。这正是设计意图——涨幅与收益是 W 形，不是越涨越好。

### 触发频率实测（22 个交易日，2026-07-14 ~ 08-12）

| 指标 | 值 |
|---|---|
| 平均池规模 | **48.1 只** |
| 平均触发 | **2.32 只/日** |
| 池内触发率 | **4.82%** |
| 市场宽度闸门通过 | **12 / 22 日（55%）** |
| **实际提醒合计** | **26 只（1.18 只/日）** |
| 其中强度 ≥70 | 约 9 只/月 |

**触发率不高。** 池子 48 只里每天约 2.3 只触发，而闸门只放行一半的交易日，所以真正到眼前的是每天约 1 只、一个月 26 只。

两个极端日说明闸门在做的事：**07-20 触发 7 只但宽度仅 31.44% → 全拦**；**07-27 宽度 93.94% → 6 只全放**。同理 08-11 触发 4 只、宽度 29.03%，全拦。

### 池子为什么是 48 只：算术必然

每日入池 `pool_top_n=10` × 窗口 `watch_days=20` = 200 个入池事件，去重后约 48，即**平均一只票能在 20 日涨幅前十待 4 天**。要缩小只有缩窗口或减每日入池数，两者都会减少样本量。

池子成员一直是「最近 20 个交易日内曾进过前十」，**本来就有界，不存在无限续期**。本轮把记录的入池日从「最近一次」改成「首次」，是语义更正确，不改变池子大小。

### 已修的四个问题

1. **回溯模式错配**（见上）。
2. **回撤显示取整会误导**：4.7% 按整数印成「5%」，而 5% 正好是加分档下沿，读的人会以为该拿分却没拿。已改为保留一位小数。

3. **强度分用错了 20 日涨幅口径**（影响每一个分数）。回测验证的是**触发日**的 20 日涨幅（分档表那一维就叫「触发日20日涨幅%」），而扫描器打分用的是**入池日**的。两者能差很远——一只票入池时涨 59%、五天后触发时可能已涨到 105%，落进完全不同的档（+30 变 +15）。已改为触发当时口径，与回测一致。

4. **`--max-alerts` 的 CLI 默认值没跟着改**：`Thresholds.max_alerts` 改成 0（不限）后，argparse 默认仍是 3，命令行照旧把 3 传进去覆盖，导致触发 6 只只提醒 3 只。两处默认值必须一致。

每轮都会往 `output/second-wave-live/scan.jsonl` **追加**一条完整记录（含未提醒的触发票、市场宽度、池子规模、每只票的三个判定数字）。复盘直接读这个文件，不必重跑。

## 4. 观察期要盯的四件事

1. **盘中判定与收盘是否一致。** 盘中 14:50 触发的票，收盘后用日 K 复核 `low ≤ MA10 < close` 是否仍成立。不一致说明动态 MA 口径需要换成静态。
2. **提醒是否刷屏。** 只数不设上限，所以这条要真盯：池子 38 只，若某轮触发十几只、或某天反复触发同一只，就得加「同一代码当日只提醒一次」的去重。日志里有每轮的触发数，观察期结束后看分布再定。
3. **弱市空仓是否有效。** 日志里记了未通过宽度闸门的轮次；观察期结束后对比「闸门拦掉的票」后续表现，验证这条免费择时条件。
4. **池子规模。** 若长期超过 60 只，说明 20 日窗口太长或入池太松，会拖慢盘中扫描。

## 5. 明确不承诺什么

- **不报预期收益。** 逐笔口径稳定（同配置三轮 +1.854% / +1.938% / +2.111%），但组合口径在 34%~98% 之间跳——信号数差 3.4% 能让组合全期差 187%。所以本脚本只报信号与依据。
- **分层未验证。** 层数按强度给（≥70 给 3 层、≥45 给 2 层、其余 1 层），是**建议不是结论**——分层收益需要分层模拟器，尚未做。
- **强度分未做前向验证。** 四项权重来自历史分档，但「强度高的后续表现更好」这件事本身还没验过。观察期要记录强度与实际结果的对应关系，这是它唯一的检验方式。
- **卖点未验证。** 模板给的是「破 MA10 止损」，与入场理由同源；但回测用的是无障碍持有 3 日，两者不是同一件事，观察期需要分别记录。
- **退市存活偏差未修。** 已退市股票行情不在库内，所有历史结论都缺这批样本。
