# 线上选股进一步性能优化 · 2026-09-12

以当前线上 `2.0.0-20260912-174908` 为基线，优化公共选股链路；没有恢复其他任务已下线的战法。测试窗口均为 2026-08-13 至 2026-09-12，实际 22 个交易日截至 9 月 11 日，使用各战法默认参数和默认股票池。

## 同环境完整执行器对照

在同一线上容器、相同依赖、相同只读热库中先后执行旧源码和隔离候选源码。完整执行器包括股票池、取证、面板、全范围前视检查、指标计算及结果整理。为取得每个交易日的完整结果指纹，脚本还执行了 dataclass 深拷贝和 JSON 哈希，所以下表不能直接当作用户点击后的 HTTP 延迟；两边使用相同观测脚本，不写候选库。

| 战法 | 原执行器秒数 | 新执行器秒数 | 提速 | 执行进程峰值 RSS（MiB） |
|---|---:|---:|---:|---:|
| 潜龙出海 V3.2 | 312.357 | 116.078 | 2.69 倍 | 609.3 → 494.6 |
| 一线定乾坤·首板次日 | 901.803 | 270.593 | 3.33 倍 | 1160.8 → 748.8 |

- 一线定乾坤·首板次日：每日选股中位数 38.802 → 10.130 秒；复用 2,230,661 行证据，紧凑常驻 29.78 MiB；面板与取证复用均实际命中。

## 进度传输压缩

原站点即使收到 `Accept-Encoding: gzip` 仍发送完整原文。现在仅对 `/api/screen/run` 启用 gzip（JSON 类型、level 1、`Vary: Accept-Encoding`）；其它路径不启用，不影响 SSE。

真实宿主 nginx 链路的同一完成响应：identity **29,473,399 字节**，gzip **2,530,691 字节**，传输减少 **91.4%**。解压后的内容与 identity 响应逐字节相同，完整证据未删减。新代理入口的 POST 启动与 GET 轮询也已跑通，单日任务 7.420 秒，区间末日因子与基线一致。

没有替换 FastAPI 编码器：真实框架对比显示备选 JSONResponse 方案更慢，实验已撤回。

## 实际改动

1. **区间复用原始面板**：首次按首日预热到末日分块读取，之后每日只截取原窗口。qfq/hfq、有效根数、停牌、每日股票池与实时日规则不变；数字缓存最多 2400 万单元，显式小池保留定向 SQL。
2. **区间复用完整取证所需事实**：原来三次扫描合为单遍；区间中进一步编码为每行 14 字节，再按每日范围精确聚合。回执和 attempts 仍完整读取，192MB 预算包括计算预留，不删证据字段。
3. **共享指标批量准备**：COUNT 的原生布尔窗口使用精确整数计数；MA/HHV/LLV 仍调用同一 pandas Cython 内核，合并逐列重复准备。特殊类型或内部 API 失配回退原公开接口。EMA/SMA 没改，评估收益较小。
4. **消除比例面板逐列构造**：板块涨停比例和潜龙市场宽度使用数组广播，规则、值、列序和扩展 dtype 处理保持一致。
5. **热库只写变化内容**：逐块完整比对近窗行情、日历、回执和 attempts；同日旁路修订仍被识别，不依赖可能漏更新的 revision。显式重建仍强制执行。

复用只存在于当前任务及连接。`total_changes`、`PRAGMA data_version` 和事务状态负责失效；预读与聚合后再次复核，超预算回退，退出释放，不增加跨日读事务，也没有跨租户结果缓存。
