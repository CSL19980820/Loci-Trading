# 公共报告：数据引用与统一渲染

本记录取代此前报告分享设计中的「每个分享令牌持久化一份 HTML」部分。视觉模板不在本轮重做范围。

## 存储与访问

公共入口 `GET/HEAD /shared/reports?token=...` 与兼容入口 `GET/HEAD /shared/reports/{token}` 调用同一读取和渲染函数。URL 只负责定位公开内容；生成 HTTP 响应时组装页面，不在磁盘生成 HTML 文件，也不为每份报告创建 JSON 文件。

`data_dir()/report_shares.db` 是一份全局分享索引。自主交易员报告的描述符只有数据库定位、周期、日期、报告版本、生成时间；完整 facts/analysis 沿用租户 palace.db 里的 guardian_reports 与 guardian_report_revisions，不再复制。小型测试样例的描述符序列化后小于 1 KiB；这不是对所有业务内容或 SQLite 实际占用的上限承诺。

独立智能体的原始运行日记有保留期。为不让已分享内容随日记清理消失，分享库仅保存其公开可读文档模型：标题、归属名、生成时间和文本章节。没有 HTML/CSS、工具原文、调用用量、账户状态或配置副本。这与日周报告重用现有历史数据的路径不同，但使用同一个公开入口和按类型复用的模板。

报告数据版本固定，展示样式共用当前模板。对历史链接更换样式不再要求重发报告或重存每一页；原令牌仍定位原报告版本，不能把旧链接悄悄切换成新判断。

## 权限与失败行为

公开请求只接受令牌，不能通过 tenant、period 或 file 等查询参数选择数据库。源路径在已打开的服务端账本发布时登记，根内路径采用相对定位以支持数据根迁移。GET 使用 SQLite mode=ro，不调用会建表或初始化账户的 Store 构造器。

索引注册原子化、同源幂等，同令牌不同来源拒绝覆盖。读取同时核对原报告令牌、版本及创建时间；当前报告正在更正时，从已保存的对应历史版本读取。索引存在但源数据缺失时返回缺失，不回退成另一个版本或残存 HTML。

保留匿名 GET/HEAD、no-store、no-referrer、noindex 和原有 CSP，并增加 nosniff。不存在的链接为 404；权限、数据库或读取故障为 503，不向访客显示内部路径。工作台 API、账号和写操作没有因公共阅读入口而开放。公共索引、源文件和祖先目录拒绝符号链接；POSIX 分享库文件为 0640，并支持 root 维护程序与数据所有者的权限交接。

## 旧链接迁移

兼容读取只处理已存在、尚未登记的旧 HTML，任何发布或 GET 都不会补写新 HTML。迁移扫描实际数据根中的旧令牌文件，只登记能从原租户账本或历史版本找回的公开内容，不把「曾生成令牌但从未发布」的报告变成公开报告。

命令随 `cli/` 进入正常部署包：

```bash
# 只读检查；数据根必须明确提供
python -m cli.migrate_report_shares --data-root /app/data

# 登记可核对的旧链接，先保留旧文件
python -m cli.migrate_report_shares --data-root /app/data --apply

# 只有动态读取验证成功、文件没有发生并发变化时才移除对应旧 HTML
python -m cli.migrate_report_shares --data-root /app/data --apply --remove-html
```

存在外置主账本时另传 `--primary-db`，不猜测位置。默认绝不删除。未知来源、令牌冲突、原文不匹配或故障均保留旧文件，结果中的 unresolved/errors 不为空时退出码为 2。迁移不修改原报告和账户，不运行模型，不重发企微。

上线顺序为：确认部署范围及现有并行改动；备份实际旧 HTML 与数据；部署含新入口的版本；只读盘点；登记索引；验证原公网链接及参数式入口；最后按批准范围清理已核验 HTML。尚未核验的旧文件不批量删除。回滚到旧发布器前必须保留或恢复对应旧 HTML，不能先清完再假定旧版本仍可读。

分享库属于持久化应用数据，应与各租户账本一同纳入一致性备份。它不是缓存，尤其独立智能体的原始日记清理后不能只靠日记重建公开文档。现有 market 专项自动备份不等于此库已被备份；本轮没有修改线上备份任务。
