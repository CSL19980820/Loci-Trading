# 项目使用规则与执行红线

本文件定义这个项目的运行边界、生成流程、用户请求到执行动作的映射，以及禁止退化成垃圾报告的红线。

## 1. 项目定位

这个项目不是“自动荐股器”，也不是“随便拼一份看起来像报告的文档”。

唯一允许的定位是：

- Python 程序负责抓取和整理结构化数据。
- Codex 负责读取程序输出、在线核验公开资料、整合为定稿。
- 最终交付必须套用固定模板输出为 Markdown / HTML / PDF。

## 2. 强制执行原则

### 2.1 真实性优先

- 没有真实 K 线，不允许输出“完整版行情报告”。
- 没有真实价格序列，不允许伪造当前价、K 线、均线、波动率、回本概率。
- 任何无法取得的数据，必须明确写成：`待核验` / `不可用` / `未取得真实数据`。

### 2.2 定稿模板优先

- 报告结构固定，必须使用 `templates/holding_report.md.j2`。
- PDF 和 HTML 必须共享同一套内容结构和封面风格。
- `assets/report-cover.png` 是默认封面模板图，除非用户明确要求替换。

### 2.3 证据链优先

- 程序数据和 Codex 在线核验必须分层。
- Codex 在线补充内容只能通过 `online_evidence.json` 合并进报告。
- 不允许在对话里临时编一段话，然后直接塞进最终 PDF。

### 2.4 失败优先于造假

- 默认模式下，缺少真实 K 线就必须失败退出。
- 只有显式传入 `--evidence-only`，才允许输出证据版报告。
- 证据版报告只展示真实取得的公告、财务、资金流和在线核验，不运行伪技术分析。

## 3. 报告模式

### 3.1 完整版报告

适用条件：

- 已取得真实 K 线
- 技术指标可计算
- 资金流、财务、公告至少部分可用

允许输出：

- 技术面快照
- 买入辅助检查
- 风险雷达
- 情景观察框架
- 完整 PDF / HTML / Markdown

### 3.2 证据版报告

适用条件：

- 没有真实 K 线
- 但已有财务、公告或 Codex 在线证据
- 用户显式接受 `--evidence-only`

必须遵守：

- 不输出伪当前价
- 不输出伪 MA/RSI/MACD/BOLL
- 不输出伪波动率与回本概率
- 相关章节保留版式，但正文必须写明“未取得真实 K 线，未运行”

## 4. 用户请求到执行动作

### 4.1 用户说“分析某只股票”

执行顺序：

1. 先跑程序取数。
2. 若真实 K 线成功，生成基础数据。
3. Codex 在线核验公告/网页/权威来源。
4. 合并 `online_evidence.json`。
5. 输出定稿 PDF / HTML / Markdown。

### 4.2 用户说“先读项目，出 PDF”

执行顺序：

1. 先按项目规则检查数据是否真实。
2. 能拿到真实 K 线则走完整版。
3. 拿不到真实 K 线则默认失败。
4. 只有用户明确接受证据版时，才用 `--evidence-only`。

### 4.3 用户说“只要证据版”

执行顺序：

1. 允许 `--evidence-only`
2. 只渲染真实取得的公告、财务、资金流和在线证据
3. 仍然输出固定模板 PDF / HTML / Markdown

### 4.4 用户说“替换样式 / 重新设计 PDF”

执行顺序：

1. 优先修改 `assets/report-cover.png`
2. 再调整 `src/toolbox.py` 的 HTML/PDF 样式层
3. 最后校验 `templates/holding_report.md.j2` 是否仍保持稳定结构

## 5. 禁止事项

- 禁止用成本价冒充当前价
- 禁止用单行伪 K 线冒充行情历史
- 禁止在没有真实价格序列时给出技术指标结论
- 禁止把“待核验”写成确定性判断
- 禁止 HTML 退化成单个 `<pre>` 文本块
- 禁止 PDF 生成失败后还宣称“已输出 PDF”
- 禁止删除空章节来掩盖数据缺失

## 6. 交付前检查

每次生成报告前必须自检：

- 是否取得真实 K 线？
- 如果没有，是否显式使用 `--evidence-only`？
- 是否有任何字段在用占位值伪装成真实行情？
- PDF 是否真实生成成功？
- HTML 是否是结构化排版，而不是 `<pre>` 降级文本？
- 是否合并了 `online_evidence.json`，且来源可追溯？

只要其中一项不满足，就不能宣称任务完成。
