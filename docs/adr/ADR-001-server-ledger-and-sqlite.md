# ADR-001：服务器单一事实账本与 SQLite

**状态**：已采纳  
**日期**：2026-07-24

## 背景

潜龙记忆宫殿需要长期保存候选、预案、成交、复盘与规则样本。主要写入者是 Agent 和单个工作台，而不是高并发多用户系统；用户希望部署后不再依赖本机长期运行，并在日后“同步”时更新服务。

## 方案对比

| 方案 | 运行复杂度 | 账本一致性 | 适配当前规模 | 结论 |
|---|---:|---:|---:|---|
| 服务器单实例 + SQLite/WAL | 低 | 强（单文件事务） | 高 | 采用 |
| 本地与服务器双向同步 SQLite 文件 | 中 | 弱（易覆盖、冲突） | 低 | 不采用 |
| PostgreSQL + 多服务/多副本 | 高 | 强 | 当前过度 | 暂不采用 |

## 决策

服务器 `/srv/qianlong-palace/data/qianlong.db` 是唯一事实源；FastAPI 单实例挂载该目录并使用 SQLite WAL。浏览器与 Agent 均通过同一个服务器 API 读写，不能直接下载、编辑或覆盖线上 SQLite 文件。

首次部署时，脚本仅在服务器没有账本时，将本机数据库用 SQLite `backup()` 创建一致性快照后导入。之后“同步”只发布代码和前端产物，绝不覆盖 `data/`、`.env` 或写入令牌。

## 后果

- 优点：部署成本低、事务审计完整、备份和迁移简单，适合单用户与 Agent 串行/低并发写入。
- 约束：服务保持单副本；SQLite 文件不能作为跨设备同步介质。
- 演进条件：出现多个独立写入服务、需要水平扩展或持续高并发写入时，再用在线迁移将账本迁至 PostgreSQL。
