## 背景

需求来自实盘经验说法：**同板块找热度高的、热度前 50、市值别太大**，尾盘买入博次日冲高。

### 落地前摸清的既有事实

- `src/intel/application/daily_recipe.py` 已有 open / intraday / close 三档结构化采集，收盘档 `_STATIC_CLOSE` 本就包含 `smart_hotlist(limit=60)` 与 `stock_screener(marketCapMinYi=30, marketCapMaxYi=200)`。当前只传 `limit`，落到默认 `platform="combined"`——**每天已经在采热度了，只是采的不是同花顺口径**。
- 悟道 MCP `smart_hotlist` 支持 `platform=ths`，周期 `hour|day|week`；参数名与同花顺真实端点一一对应。
- `entry_timing` 已支持 `close`（尾盘入场），前视审计在 `src/strategy/application/audit.py`：`close` 档裸用当日 `high`/`low` 会被 block。
- `quotes_daily.outstanding_share`（流通股本）是一等面板字段（`PANEL_FIELDS`），流通市值 = `close × outstanding_share` 本地可算、有完整历史。**总股本本地没有**。
- 热度快照当前只落 `market.db.intel_snapshots`：主键 `(trade_date, tool, args_hash)` + UPSERT 覆盖，定位为"可整表删除重建"的缓存。

核心矛盾：**日 K 删了能重拉，热度榜删了永远补不回来**。仓内已有先例——`leader_role_snapshots` 正是因为 `intel_snapshots` 会覆盖、抹掉盘中演进，才另建只追加表。

### 调研结论对本 ADR 的冲击

一手调研（见上方报告）一句话结论：**数据比想象的好拿，逻辑比想象的差**。

| 调研发现 | 对本 ADR 的影响 |
|---|---|
| 同花顺热榜零鉴权可直连（实测 100 行个股 + 20 行板块），但**只有当前快照没有历史** | 历史瓶颈比取数难得多，决策 1 因此修订 |
| 个股榜每行自带 `tag.concept_tag` 中文概念标签 | 决策 5 改为同源本地聚合，不再借开盘啦口径 |
| 接口原生带 `hot_rank_chg` 与 `tag.popularity_tag`（"首次上榜"） | 决策 4 的增量取值方式简化 |
| 东财人气榜有 5 年历史排名，akshare 已在仓内依赖 | **不必等两个月**，现在即可回测证伪 → 决策 1 |
| 注意力因子在 T+1~T+20 尺度偏证伪（Robinhood 榜前列 20 日异常收益 −4.7%；A 股百度指数次日方向为负） | 决策 4 方向正确但需正反双向验证 |
| 实测热榜前 50 过 200 亿闸只剩 17 只，砍掉的是龙头、留下的是反转最强的跟风股 | 决策 6 存在逆向选择风险，需"不设市值闸"对照组 |
| akshare 无同花顺热度函数（`stock_hot_rank_wc` 已静默移除）；pywencai 需 Node + 人工 cookie 且作者反对商用 | 排除这两条路 |

## 决策

1. **三步走，先证伪再建**（原「两步走」经调研修订）。

   - **第 0 步（先做）**：用东财人气榜 5 年历史排名（`stock_hot_rank_detail_em`，akshare 已在仓内依赖）做代理回测，**正反两个方向都跑**——「选热度高」与「避热度高」。若代理口径下为负期望，整件事到此为止，省掉后续全部工作量。
   - **第 1 步（并行，一行改动）**：`daily_recipe.py` 的 open / close 两处 `smart_hotlist` 各加 `platform="ths"`，当天起 `intel_snapshots` 开始积累同花顺口径热度，为将来同源回测攒历史。零风险、可回滚。
   - **第 2 步（仅第 0 步为正才做）**：按下述决策实装选股器与纸面舱。

   代理口径的局限须写进结论：东财榜只有排名没有热度值，是东财用户群不是同花顺用户群，两榜重叠度未测。但若连代理口径都是负期望，指望换平台转正没有依据。

   ### 第 0 步执行结果（2026-08-12，判定：负期望）

   东财路线实测走不通——本机到 `emappdata` / `push2.eastmoney.com` 的 TLS 全断（Fake-IP 劫持），且 akshare 1.18.56 没有按日期返回当日榜的函数，历史全是逐票查，重建"每日榜前 50"要扫全市场 5,500 只。改用**本地可算的注意力代理**（Barber & Odean 2008 的原始代理：异常成交量 + 极端日收益，加换手率与成交额），624 个交易日、票池 4,992。详见 [`2026-08-heat-tail-attention-proxy-backtest.md`](../research/2026-08-heat-tail-attention-proxy-backtest.md)。

   - **信号有效**：决策 2 的标签（次日最高 ≥ 今收 ×1.03）命中率从池子基准 22.50% 抬到 38–47%，是低关注度组 12.25% 的 3–4 倍。
   - **但放大的是双向波动**：同批票次日下探 −3% 的概率也从 20.76% 抬到 52–74%。
   - **亏损全在隔夜**：所有热度臂的次日盘中收益都是正的（+0.50% ~ +0.95%），隔夜跳空吃掉更多（−0.96% ~ −1.98%，池子基准仅 −0.10%）。
   - **T+1 堵死了最直观的修法**：当日买入当日不可卖，要在 T+1 盘中卖必须 T 日尾盘先持有，隔夜躲不开。
   - **换执行时点大幅改善但仍为负**：入场从尾盘挪到次日开盘，每笔均净 −1.3% → −0.25%、胜率 32% → 45%。反算毛收益最好格约 **+0.11%/笔，不到 26bps 往返成本的一半**。
   - 第二轮改用宽池子切片 + 交叉组合搜索（见「后果」），把先验全部反过来也**没有前后两段都为正的组合**。
   - 因此按本决策约定，**第 2 步不实施**。第 1 步的同花顺口径采集保留：每天 2 次调用换未来的同源复核可能性，成本可忽略。

   **决策 1 本身的价值**：这套判定用了不到一天，若按原「两步走」先建选股器 + 纸面舱攒两个月，会在两个月后得到同一个结论。

2. **"冲高"的可计算定义 = 次日盘中最高价 ≥ 当日收盘 × 1.03**。只问次日给不给出货机会，不要求收得住。理由：尾盘买入者的真实诉求是次日有无冲高卖点，且最高价可客观核验、不依赖持仓假设。该标签同时是每日回填字段与验收口径。

   调研佐证：A 股平均隔夜收益（收盘→次日开盘）显著为负，所以"尾盘买、次日冲高卖"赌的是**次日盘中路径**而非隔夜跳空——出场必须是次日盘中止盈或收盘，不能默认开盘卖。

3. **热度主口径 = 同花顺榜 ∩ 综合榜双前 50**。以 `platform=ths` 为主，与 `platform=combined` 取交集，两榜均进前 50 才入池，宁缺勿滥。其余各档（`ths` 的 hour/day、`eastmoney` 等）照样每日落盘备用——多存几个榜每天只多 3–4 次调用，相对 structured 池 3000/天可忽略。

   `rate`（热度值）口径未公开：官方规则页需登录（实测 401），未能从一手来源确认其构成。**只能当不可解释的黑箱分**，不得声称它是搜索热度或自选热度。因此热度优先当**分类特征**（在不在榜）而非连续因子——`rate=760487` 比 `rate=428474` 高多少没有可解释意义。

4. **热度取增量而非存量**。绝对排名前 50 只用来定池子，池内排序按注意力增量而非热度水平。依据是注意力因子的既有结论：稳坐榜首意味着注意力已被定价，驱动次日冲高的是注意力增量。

   **取值方式（调研后简化）**：同花顺热榜接口原生带 `hot_rank_chg`（排名变化）与 `tag.popularity_tag`（`"首次上榜"` / `"持续上榜"` / `"2天1板"`），比"开盘档 → 收盘档两档差分"更直接、更省调用。"首次上榜"正是注意力冲击刚开始、正向段尚未耗尽的状态，是本决策最想抓的一类。两档差分保留为悟道 MCP 口径下的替代算法（MCP 不返回 `hot_rank_chg`）。

   调研**强化了本决策的必要性**：注意力正向段在 A 股最多到"当日"，而热榜盘中实时更新，14:50 看到的高热度水平，正向部分基本已体现在当天那根 K 线里。

5. **板块归属改用个股榜自带的概念标签，与个股热度同源**。个股热榜每行都带 `tag.concept_tag`（中文概念标签数组，实测如 `["流感","医药电商"]`），"同板块找热度高的"所需的板块归属**就在个股榜里**，本地聚合即可，零额外调用、零口径混用。

   同花顺板块热榜（`/plate?type=concept`）实测可拿（20 条，带 `rate` 与"连续 268 天上榜"类持续性标签），但只能直连，且与个股榜存在**口径断层**：板块榜给同花顺概念指数代码（`886033`），个股榜给中文概念名，两者无共同 id，只能靠名称字符串关联。故第一步不依赖板块榜。

   板块成立条件保持"抱团确认"：同一 `concept_tag` 下热度股 ≥ 2 只。开盘啦（KPL）`theme_intraday_capital` 强度榜降为**可选的资金确认层**（默认关，因与同花顺热度不同源，存在题材归属口径差）。孤苗一只热度高按个股事件处理，不算板块发酵。

6. **市值层以本地流通口径为主闸**：流通市值 ≤ 400 亿且流通股本 ≤ 20 亿股，不设硬下限，盘子越小排序越靠前；用户原话的"总市值 ≤ 500 亿"降为 MCP 侧辅助粗筛（有则用，缺失不阻断）。

   理由：流通市值本地可算、有完整历史、可回测；总股本本地没有，总市值只能靠 MCP 实时筛且无历史。主闸若用总市值，实时面板与回测将是两套口径，攒再久也无法对照。

   股本闸不与流通市值重复：流通市值已同时吃掉股本与股价，股本闸唯一多挡的是"低价 × 巨股本"的僵尸票（如 3 元 × 80 亿股 = 240 亿流通市值，数字正常但筹码撬不动）。

   所有阈值复用 `watch_tuning` 既有的 `FIELD_META` + 进攻/中性/防守三档预设机制，界面可调，不锁死。

   **调研发现的逆向选择风险**：实测热榜前 50 过 200 亿流通市值闸后只剩 17 只，砍掉的恰是龙头（工业富联 13,018 亿、中际旭创 10,223 亿、紫金矿业 6,918 亿），留下的恰是反转效应最强的跟风股。同时 200 亿覆盖全市场 83.8% 的股票，**本身根本不是小市值筛选**，只是一个"把热榜从龙头股换成跟风股"的风格暴露（学术锚点：Liu/Stambaugh/Yuan 2019 的 CH-3 规模因子明确剔掉最小 30% 的壳股，与"保留小票"方向相反）。本 ADR 取 400 亿更宽、杀伤力小一些，但方向性风险同在——**第 0 步回测必须把「不设市值闸」作为对照组一起跑**。

7. **尾盘涨幅闸取 -3% ~ +7%，分两类展示**。主池「顺势冲高」0% ~ +7%，旁池「回调低吸」-3% ~ 0%。硬剔除两类：已封涨停（尾盘根本买不进，尤其一字/T 字）与涨幅 > 7%（次日高开即套）。

8. **落点选 `skill_watch` 盘中扫描通道**，新增「监测·热度尾盘」，在盘中窗口的尾盘那一轮出票。

   理由：`skill_watch` 的扫描链本就是 `payload`（悟道载荷解析）+ `kline_stats`（本地日线派生指标）的组合，与"外部热度 + 本地流通市值"同构；且它自带 `watch_tuning` 可调阈值、只追加留痕、企微推送与纸面舱接入，正好是决策 1、3、6 需要的设施。盘中扫描窗口 `13:00–14:50` 天然覆盖尾盘。

   排除 `screen` 引擎通道：公式引擎只能读本地面板字段（`PANEL_FIELDS`），外部热度进不去，走这条得另造一套注入机制。

   **命名澄清**：现有 `sanyuan-tail-v1`「三源尾盘共振」虽名为尾盘，实为 15:30 盘后选股、`entry_timing="next_open"`、次日开盘买入、T+2 收盘卖出，与本 ADR 的"当日尾盘买入"不是一回事，**不复用、不扩写**，避免污染其既有回测记录。

9. **输出四路：界面面板 + 尾盘企微一条 + 只追加热度候选事实表 + 独立纸面舱自动模拟买入**。不写 `palace.db`：未验证的扫描结果入账本等于提前赋予其权威地位。纸面舱是验证主手段，两个月后看到的是真实纸面盈亏，比回填标签硬。纸面舱与龙王舱隔离，不共用仓位。

10. **纸面卖出：次日 -3% 止损、+3% 止盈，两边都不触则次日收盘卖**。买入价取尾盘实价（≈当日收盘），与决策 2 的标签基准同源。

    两条保守约定（不另行决策，直接实现）：日 K 只有 OHLC，同日既触止损又触止盈时无法判定先后，**一律按先止损计**；次日一字跌停卖不掉则顺延至可成交日，不假装已出清。

11. **每日最多 3 只，纸面每只 1/3 仓；不足 3 只就出几只，一只不符合即当日空仓**。绝不放宽阈值凑数（沿用 `sanyuan-tail-v1` 弱市整日空仓的既有先例）。

12. **两段式出票**：14:45 推「预备名单」一条，14:52 推「最终名单」一条，纸面舱按 14:52 那轮成交。沪深两市 14:57 进收盘集合竞价，最晚有效下单约 14:56，14:52 定稿留约 4 分钟。需把 `DEFAULT_WATCH_SCHEDULE` 的盘中窗口末端从 `14:50` 延到 `14:52` 之后。

    **14:50 信号 ≠ 按收盘价成交**：涨停、封板、停牌、价格笼子拒单、收盘竞价成交概率都要 veto，规则依据见 `2026-08-tail-close-indicator-source-review.md`（已从仓库移除，可在提交 d05e02d 中查看） 收录的交易所规则页。

13. **热度源降级：第一步软跳过，第二步走 tape lane**。

    第一步（MCP 单源）按仓规铁律：先查 `wudao_availability()`，不可用时 Job 记 `skipped`、面板显示"热度源不可用"、纸面舱当日不建仓，**不得**拖垮盘面、账本、本地选股与行情同步。

    第二步（若第 0 步为正）按 [ADR-009](ADR-009-market-tape-provider-lanes.md) 加**第 7 条 tape lane**（如 `hot_rank`），两个 provider：同花顺直连 + 悟道 `smart_hotlist(platform=ths)`，first-healthy-wins。MCP 不可用（未配 Key / 免费档 09:15–10:30 停服 / 配额耗尽）回落直连；直连挂（同花顺改版）回落 MCP；全挂则 `degraded`，战法降级为不带热度的版本而非阻断。复用既有 `TapeRequest` / `TapeResult` / `TapeProvenance` 契约与 `intel_snapshots` 缓存，**不新建表**。

    **不用东财/雪球热度顶替同花顺口径出票**（口径不同源，换源即换策略）；东财仅用于第 0 步的历史代理回测。

14. **留痕表 `heat_tail_candidates`（ops.db，只追加）**：与 `leader_role_snapshots` 同构——`intel_snapshots` 是按 `(交易日, 工具)` 覆盖的可重建缓存，而热度榜是**不可重建的时点事实**，今天没采到永远补不回来。

    字段：`id TEXT PRIMARY KEY`、`trade_date`、`scan_at`、`stage`（`prelim`/`final`）、`code`、`name`、`ths_rank`、`combined_rank`、`hot_rank_chg`、`popularity_tag`、`concept_tags`（JSON）、`concept_cluster_n`、`float_mv`、`outstanding_share`、`pct_chg`、`bucket`（`trend`/`dip`）、`close`、`picked`；索引 `(trade_date, stage)`。

    **只存观测事实**。次日最高价、是否达 +3%、胜率等一律可从 `quotes_daily` 推导，按仓规不入库，在 application 层即时算。保留天数交由既有 `MANAGED_PRUNE` 管理。

15. **漏斗每一级必须出回执，禁止静默丢票**（调研 C3 实测结论）。热榜 N 只 → 本地可定价 M 只 → 市值闸拒 K 只 → 涨幅/涨停/ST/停牌拒 J 只，逐级留数。

    新股缺口是**结构性**的而非偶发：实测 50 只里 `688825`（长鑫科技）本地 `quotes_daily` 根本没有，而热榜天然偏爱新股次新股，它们恰恰是本地行情仓最晚补齐的。静默丢弃会让"今天只有 3 只候选"与"今天有 8 只但 5 只定不了价"看起来一模一样。口径与 `src/intel/README.md`「裁剪要留痕」一致。

16. **热度快照必须自报时刻**。同花顺 hour 榜滚动更新，14:50 的信号若用了 09:31 的快照就是拿早盘冒充实时。既有 `cache_fetched_at` / `cache_age_minutes` 机制必须透传到战法证据里，超龄快照按不可用处理。

17. **合规边界**（调研 A6，工程判断非法律意见）：`dq.10jqka.com.cn/fuyao/*` 每天一到几次请求、单机自用、不再分发。禁止随机 UA 轮换、多 IP 轮转等反检测手段。akshare（MIT）/ adata（Apache-2.0）的代码许可**不授权同花顺返回的数据**，与 `2026-08-market-data-source-intake.md` 既立的规矩一致。不抄 adata 的 header 层（其源码硬编码了 2023 年的真实抓包 cookie）。问财（iwencai）整条路排除：`robots.txt` 明确 `Disallow: /search` + `Crawl-delay: 10`，且需 Node 运行时与人工 cookie。

## 后果

### 第 0 步回测对各决策的逐条判定

| 决策 | 判定 | 依据 |
|---|---|---|
| 2 「冲高」= 次日最高 ≥ +3% | **标签有效** | 命中率 22.50% → 38–47%，区分度充分 |
| 4 取增量而非存量 | **正确** | 增量臂均净 −1.32% / 胜率 32.0%，存量臂 −2.55% / 22.3% |
| 4 的「首次上榜」子项 | **无独立贡献** | 1,838 vs 1,851 样本（差 0.7%）；按增量选 top3 时 99.3% 本来就是刚进榜的票 |
| 5 抱团确认 | **不显著** | 尾盘格略优、次开格略差，方向不一致；本地用 industry 顶替 concept_tag，不足定论 |
| 6 市值闸 | **符号错了，不只是没用** | 第二轮宽池子切片显示胜率随流通市值**单调上升**：<50亿 22.93% → ≥1000亿 40.84%。用户原话"市值别太大"与本决策的 400 亿上限都在挑最差那一档 |
| 3 「热度前 50」 | **能用的是尾部不是头部** | 排名 01-10 名胜率 23.29%，41-50 名 30.48%，单调。注意力过热即已定价 |
| 7 的「尾盘走强」直觉 | **无信息** | 收盘位置 CLV 四档胜率相差不到 1 个百分点 |
| 10 保守止损约定 | **成立但代价巨大** | 热度组"同日两边都触"11.67%，是基准 6 倍、低关注组 36 倍；用它跨波动率比较不公平 |
| 12 尾盘 14:52 出票 | **被否定** | 尾盘入场是全网格最差执行时点 |

结论：**选股逻辑方向没错，执行时点错了；而 T+1 使正确的执行时点不可达。** 这也解释了既有
`sanyuan-tail-v1`「三源尾盘共振」为何名为尾盘却用 `entry_timing="next_open"`——前人踩过同一个坑。

### 第二轮：把先验全部反过来也找不到稳定 edge

第一轮的方法本身有毛病：预设整套闸门再验证，等于先信了策略。第二轮改成只留三条无争议硬条件
（注意力前 50 ∩ 主板或创业板 ∩ 非涨停）、池内全部等权跑，再按 9 维切片 + 2~3 维交叉搜索
（n ≥ 1000，强制前后两段各报一次）。

- 按切片把先验**全部反过来**（要大市值、要热度榜尾部、要低换手低量比、要昨未涨停），
  次开买口径确实能把毛收益推到微正。
- 但交叉组合 top20 **无一在前后两段都为正**：尾盘买两段皆负（前段 0/20、后段 0/20），
  次开买 17/20 前段为正而后段 **0/20**。最优组合全样本 +0.079% = 前段 +0.639% / 后段 −0.680%。
- **后段清零不是样本不足，是效应在后半段整体翻转。** 前半段那些数字靠 2024 到 2025 上半年撑着。

因此判定从"执行时点错了"收紧为：**在本代理口径下，无论怎么选、怎么执行，都没有可持续的 edge。**

### 胜率与盈亏比（保本胜率 = 1 / (1 + 盈亏比)）

| 执行 | 笔数 | 胜率% | 盈亏比 | 保本胜率% | 缺口 | 盈利因子 |
|---|---|---|---|---|---|---|
| 全池 尾盘买·T+1卖 | 31,068 | 27.60 | **0.793** | 55.77 | **−28.17pp** | 0.302 |
| 全池 次开买·T+2卖 | 30,970 | 40.53 | **1.126** | 47.04 | −6.50pp | 0.768 |
| top3 尾盘买（A） | 1,852 | 31.97 | 0.850 | 54.07 | −22.10pp | 0.399 |
| top3 次开买（F，无市值闸） | 1,843 | 45.09 | 1.132 | 46.90 | **−1.81pp** | **0.930** |
| 次开买 ∩ 流通市值 ≥1000亿 | 260 | 43.08 | 1.295 | 43.57 | **−0.50pp** | 0.980 |

**尾盘买的盈亏比 0.793 < 1 是隔夜效应的第二个独立证据**：障碍对称 ±3%，但均亏 3.846% 大于均赢
3.049%——T+1 开盘跳空跌破 −3% 时按更差的开盘价成交，而向上跳空超 +3% 罕见得多。

尾盘买口径下**没有任何一格盈利因子超过 0.62**。次开买最好的格盈利因子 0.980、差 0.5pp 保本，
但样本仅 260 笔且在后半段翻负——差一点点不等于再调调就能过。

- **优点**（第 2 步若将来重启仍成立）：全部复用既有设施——`skill_watch` 扫描链、`watch_tuning` 三档预设、只追加留痕、企微推送、纸面舱、`MANAGED_PRUNE`、tape lane 骨架，不新增第二套机制、不新建 SQLite 表（除只追加事实表）。主闸口径（流通市值/流通股本）本地可算且有历史，保证面板与回测同尺。第 0 步用已有依赖先证伪，把最大的一笔工程投入放在有证据之后。

- **约束与风险**：
  - **方向性风险最大**：一手证据在 T+1~T+20 尺度上偏证伪。决策 4（取增量）与决策 1（正反双向回测）是应对，但若第 0 步为负，本 ADR 的第 2 步不予实施。
  - 决策 6 的市值闸存在逆向选择（砍龙头留跟风），必须有"不设市值闸"对照组。
  - 同花顺热榜是 App 私有接口：无文档、无 SLA、无版本承诺，改版即挂且不会有公告；`rate` 口径是黑箱。
  - 免费路径下同花顺热度**无历史**，同源回测需从第 1 步起自采数月，或走 Tushare `ths_hot`（6000 积分，有 `trade_date` 与采集时点标注）。
  - 每日最多 3 只、两个月约 40 个交易日，样本上限约 120 笔，只够方向性判断，不足以支撑精细参数寻优。
  - `sanyuan-tail-v1` 名为"尾盘"实为次日开盘买入，产品文案须明确区分「尾盘买入」与「盘后选股」。
  - **本机出站链路**：本工作站 DNS 被隧道客户端劫持为 Fake-IP，无法直连 `10jqka.com.cn` 与 `push2.eastmoney.com`。走直连方案前必须先按 `src/intel/README.md` 第 36 行那套 Fake-IP 修正验证出站可达，否则实现完了在本机也跑不起来。**任何"同花顺连不上"的结论都要先排除这一层**，别把环境问题写成供应商封禁。

- **调研已答的原待验证项**：
  - 注意力因子 T+1 尺度方向 → **偏反转**，见调研 B1/B2/B5。
  - 是否存在带历史的热度源 → 同花顺无（免费路径）；东财人气榜有 5 年排名史；Tushare `ths_hot` 有历史但收费。
  - 同花顺板块热度能否拿到 → **能**（直连 20 条），但个股榜的 `concept_tag` 已够用，见决策 5。

- **仍未验证**：`rate` 的确切构成（官方规则页 401）；同花顺 App 榜与接口榜是否同源；`type=day`/`week` 的返回形态；各热度源之间的重叠度（因此"换源代价"无法量化）；MCP `marketCap` 参数究竟是总市值还是流通市值。

- **已落地**：仅决策 1 第 1 步——`src/intel/application/daily_recipe.py` 的 open / close 两档各加一条
  `smart_hotlist(platform="ths")`，与既有 `combined` 综合榜并存（不同参数即不同缓存行）。
  `src/intel/README.md` 已同步「热度双口径」条目。`tests/intel` 101 项通过。

- **未实施**（第 2 步，判定为负期望后冻结）：`src/ops/application/skill_watch/` 新扫描器与
  `engine_registry` 注册、`tuning.py` 的 `FIELD_META` 阈值登记、`heat_tail_candidates` 表、
  `DEFAULT_WATCH_SCHEDULE` 窗口延至 14:52、独立纸面舱、前端新面板。若将来拿到真同花顺
  `rate` 历史并复核为正期望，按上述落点重启，届时需补 `tests/ops/` 覆盖筛选链、阈值登记、
  只追加写入、逐级回执与空仓分支，且外部 HTTP 全部 mock。

- **重启这件事的最小条件**：拿真 `rate` 历史（Tushare `ths_hot`，6000 积分，带 `trade_date` 与
  采集时点）或第 1 步自采数月后的同源快照，重跑
  [`heat_tail_attention_proxy_research.py`](../../scripts/heat_tail_attention_proxy_research.py)
  的执行网格与 [`heat_tail_pool_slice_research.py`](../../scripts/heat_tail_pool_slice_research.py)
  的切片＋交叉搜索。门槛：至少一个组合**前后两段都为正**，且毛 edge 显著超过 26bps 往返成本。

- **复核时最该盯的偏差**：本地代理选出的票比真热榜更极端——宽池子里当日涨幅落在 −2%~+2% 的
  只占 0.4%，而上游调研实测的真同花顺 hour 榜前 5 里就有风华高科 `+1.00%`（第 4 名）。真 `rate`
  由端内浏览与自选驱动，会收进温和波动的票；代理（换手 0.30 + 量比 0.30 + 成交额 0.25 +
  |涨幅| 0.15）不会。**代理组的反转特征因此更重，本轮负期望有一部分来自这个偏差。**

- **若将来只想保住一条可用结论**：切片显示的方向比任何具体参数稳——市值越大越好、热度排名
  越靠后越好、换手与量比越低越好、昨日涨停的更差、收盘位置无信息。这五条在两个执行口径下
  方向一致，且与"注意力过热即已定价"自洽；不稳的是它们能不能凑出超过成本的收益。
